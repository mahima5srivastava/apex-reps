## Bucket Policies

| Policy                                        | Command  | Role            | Condition                       |
| --------------------------------------------- | -------- | --------------- | ------------------------------- |
| `authenticated users can upload their photos` | `INSERT` | `authenticated` | `bucket_id = 'progress_photos'` |
| `authenticated users can view their photos`   | `SELECT` | `authenticated` | `bucket_id = 'progress_photos'` |

**Notes:**

- No `UPDATE`/`DELETE` policies — objects are immutable once uploaded
- App handles "delete" via rollback on failed check-in (removes uploaded objects via storage API)
- No direct user-facing delete — photos persist with their check-in

## Object Path Format

```
{userId}_{statId}_{angle}.{extension}
```

**Examples:**

- `a1b2c3d4-..._e5f6g7h8-..._left.jpg`
- `a1b2c3d4-..._e5f6g7h8-..._front.jpg`

**Generated by:** `buildPhotoStoragePath(userId, statId, angle, extension)` in `app/utils/constants.ts`

---

## Access Pattern

1. **Upload** (check-in): Client compresses image → `supabase.storage.from('progress_photos').upload(path, file)`
2. **Read** (dashboard): Server generates signed URL → `createSignedUrl(filename, 60*60*24*7)` (7-day expiry)
3. **Rollback** (on error): `supabase.storage.from('progress_photos').remove([paths])`

| Parameter                 | Value                     |
| ------------------------- | ------------------------- |
| Max dimension             | 1000px (longest edge)     |
| Output format             | JPEG                      |
| Quality                   | 0.82                      |
| Allowed input types       | `image/jpeg`, `image/png` |
| Max file size (validated) | 10MB                      |

---

## RLS Interaction

Storage policies work at the **bucket level**, not object level. The policies allow any authenticated user to:

- Upload to `progress_photos` bucket
- Read from `progress_photos` bucket

**Object-level isolation** is achieved by:

1. Prefixing paths with `userId` — users only know their own paths
2. Application only generates signed URLs for photos linked to user's stats (via `photos` table RLS)
3. No LIST policy — users cannot enumerate bucket contents

## Migration Reference

```sql
-- 20260824220000_storage.sql
insert into storage.buckets (id, name, public)
values ('progress_photos', 'progress_photos', false)
on conflict (id) do nothing;

create policy "authenticated users can upload their photos"
  on storage.objects
  for insert
  to authenticated
  with check (bucket_id = 'progress_photos');

create policy "authenticated users can view their photos"
  on storage.objects
  for select
  to authenticated
  using (bucket_id = 'progress_photos');
```
